# Контекст: анимация и моушен

Портфолио на Astro 7 (статическая генерация, деплой на GitHub Pages). Вся
анимация — **чистый vanilla TypeScript** в `src/scripts/*.ts`, подключённый как
`<script src="...">` в `Shell.astro`. Никаких анимационных библиотек — скролл
нативный (браузерный), без JS-прослойки.

## Что уже анимировано

### 1. Скролл всей страницы — нативный, без библиотеки
Раньше здесь стоял **Lenis** (`smooth-scroll.ts`, инерционный скролл через
реальный `scrollTop` на каждый кадр). Убран целиком — не просто отключён,
а физически удалён из `package.json`/`Shell.astro`/`global.css`.

**Почему убрали.** Замер на реальном устройстве (Safari Web Inspector →
Timelines) на этой странице стабильно показывал кадры по 60–70ms (норма для
60fps — 16.6ms) при скролле мимо hero, с Composite/Layout, размазанными по
всему кадру, а не точечно. Методом исключения по одному убирали кандидатов
(вебвизор Яндекс.Метрики, CSS-переход хедера, `will-change` reveal-карточек,
саму reveal-анимацию) — фриз оставался при каждом удалении, пока не отключили
Lenis: тогда фриз пропал полностью. По независимому источнику (GitHub-тред
Lenis, обсуждение аналогичного кейса) мейнтейнер называет настоящей причиной
таких симптомов не саму библиотеку, а перегруз paint/decode от изображений
завышенного разрешения на каждый кадр скролла — то есть технически более
«правильный» фикс — адаптивные `srcset`/`sizes` для картинок, а не удаление
Lenis. Решение убрать Lenis всё равно было осознанным: на этом устройстве это
уже проверенно работает, плюс Lenis ощутимо меняет характер скролла
(инерция/непредсказуемость по сравнению с нативным) — если решите вернуть
smooth-scroll в будущем, сначала стоит довести до конца адаптивные картинки
(`src/scripts/responsive-widths.ts`, если к тому моменту существует) и
перепроверить профиль заново, а не переустанавливать библиотеку вслепую.

### 2. Scroll-linked reveal карточек — [src/scripts/reveal.ts](src/scripts/reveal.ts)
Референс: блок "Projects" на humanmade.co.jp. Карточки (`data-reveal`) выезжают
из правого нижнего угла синхронно со скроллом, и **уезжают обратно**, если
скроллить вверх (не одноразовый triggered-анимация, а честно scroll-linked).

Механика: позиция — не жёсткий 1:1 маппинг скролла, а демпфированное
приближение (`lerp`) текущего значения к линейной scroll-цели, с постоянной
времени `TAU`. Так на humanmade сделано через GSAP ScrollTrigger `scrub: 1` (+
Lenis) — здесь это переизобретено вручную через `requestAnimationFrame`:
```
TAU = 0.22        // постоянная времени демпфирования, сек. Больше = тягучее, меньше = резче
START = 1.2        // прогресс p=0 когда верх карточки на 1.2×vh (на 20% ниже нижнего края экрана)
END = 0.5           // прогресс p=1 когда верх карточки на середине экрана (0.5×vh)
```
Только `transform: translate()`, **без opacity** — было убрано осознанно (юзер
попросил "движение без затухания"). Смещение: 40×64px десктоп, 24×40px мобильная
(токены в `global.css`, `html.reveal [data-reveal] { transform: ... }` — это
только стартовое/fallback-состояние до первого JS-кадра, дальше JS каждый кадр
переопределяет `el.style.transform` напрямую).

Выключается при `prefers-reduced-motion: reduce` (класс `html.reveal` не
ставится вовсе — карточки просто видны без смещения).

Применяется через `data-reveal` на обёртке `.reveal-slot` вокруг карточек кейсов
на главной (`index.astro`) — **и продуктовых, и исследовательских, и в мобильном
дереве**. Playground явно исключён из reveal по просьбе пользователя ("анимацию
пока не нужно").

**`will-change: transform` — точечно через JS, не статикой в CSS.** Раньше был
статичный `html.reveal [data-reveal] { will-change: transform }` — держал все
8 карточек (крупные обложки) промоутнутыми отдельным GPU-слоем весь сеанс, даже
давно остановившись; профиль (Safari Timelines) показал `Composite: 37ms` из
`66ms` кадра — больше половины времени кадра на пересборку постоянно висящих
слоёв без причины. Теперь `reveal.ts` сам включает `will-change` на элементе
только пока тот реально едет (`elActive`), и снимает (`auto`) сразу после
остановки. Дополнительно — `PROMOTE_LEAD = 0.35`: слой промоутится с запасом
(~250–300ms при обычной скорости скролла) ДО того, как элемент реально
трогается, а не в один кадр с первым видимым сдвигом — первая постановка
`will-change` не бесплатна (браузер растрирует карточку в новую GPU-текстуру),
и без запаса эта растеризация совпадала с первым кадром движения, ощущаясь как
маленький фриз ровно в момент старта анимации карточки.

### 3. Переключение языка (RU/EN) — [src/scripts/scramble.ts](src/scripts/scramble.ts)
Текстовый "scramble"-эффект (посимвольная замена случайными буквами/цифрами на
пути к финальному тексту), похоже на классический text-scramble-эффект. Скорость
кадра `FRAME_MS = 16` (~60fps), у каждого символа свой случайный интервал
старта/финиша замены — получается волна, не синхронная смена всех разом.
**Успокаивается за 15–40 секунд** на длинных абзацах — это ожидаемо медленно,
не баг, при замерах после переключения языка нужно подождать.
Неразрывный пробел (` `) не подменяется случайным символом — иначе на время
анимации перенос строки скачет.
Высота элемента на время анимации залочена (`lockHeight`) под максимум
до/после-состояния, чтобы скремблящийся текст не дёргал раскладку соседних блоков.

### 4. Lightbox (полноэкранный просмотр) — [src/components/Lightbox.astro](src/components/Lightbox.astro)
- Открытие/закрытие: `opacity` transition 200ms ease на оверлее.
- Зум: клик/тап — переключение между "вписанным" видом и `maxScale` (зум к точке
  клика), колесо мыши + Ctrl (или pinch на трекпаде) — плавный zoom, touch —
  pinch-to-zoom и drag двумя/одним пальцем. Формула допустимого зума:
  `maxScale = clamp(MIN_ZOOM=1.5, native_pixel_ratio, MAX_ZOOM=12)`.
- Перетаскивание — clamp по границам вписанного изображения, зависит от текущего
  scale (нельзя утащить картинку за пределы видимой области).
- **Никакого CSS-transition на zoom/pan** — интерактивные жесты рендерятся
  напрямую через `el.style.transform` каждый кадр (плавность даёт сам поинтер),
  transition 200ms используется только на дискретных прыжках (тап-зум, ресет).

### 5. Before/After слайдер — [src/components/BeforeAfterSlider.astro](src/components/BeforeAfterSlider.astro)
Десктоп: перетаскиваемая шторка через `<input type=range>` (прозрачный, поверх
картинок), позиция — CSS-переменная `--pos`, обновляется на `input`-событии без
анимации (1:1 с пальцем/мышью). Мобильная (`< 576px`): **не** перетаскивание, а
переключатель-таб (два состояния — "Старый вариант"/"Новый вариант"), см.
`context-design.md` за деталями — это дизайн-решение, не моушен, но упомянуто
здесь, т.к. на десктопе слайдер драг-анимационный, а на мобильной — нет.

### 6. Точки hero подсвечиваются под курсором — [src/scripts/hero-dots-spotlight.ts](src/scripts/hero-dots-spotlight.ts)
Второй, ярче закрашенный слой той же точечной сетки (`.spotlight-dots`,
`fill: var(--color-black-64)`) поверх базового в [Bio.astro](src/components/Bio.astro)
— **не переопределение существующего слоя**. Базовый слой и его затухание к
краям (`hero-dot-fade`, `objectBoundingBox`, `r=0.5`, `gradientTransform:
scale(0.965 1)`, стопы `20%/90%`) остаются буквально нетронутой исходной
разметкой из Figma — JS их вообще не касается. Это осознанный выбор именно
ради того, чтобы состояние покоя (курсор вне блока) гарантированно совпадало с
макетом пиксель-в-пиксель: раньше пробовали двигать центр самого базового
градиента, и любая правка JS-формулы радиуса/позиции чуть уводила состояние
покоя от исходного дизайна — с отдельным слоем эта категория бага
структурно невозможна.

Спотлайт-слой вырезан отдельной маской (`hero-spotlight`,
`gradientUnits="userSpaceOnUse"`, фиксированный `r=150`px), чей центр
(`cx`/`cy`) лерпится к позиции курсора каждый кадр через `setAttribute` (без
CSS-transition на позицию — как в Lightbox: интерактив рендерится напрямую).
Демпфирование — та же lerp/TAU-схема, что в `reveal.ts`, но резче (`TAU
0.12`) — локальный отклик под курсором, а не сдвиг через весь экран.
Видимость слоя переключается классом `is-active` по `pointerenter`/
`pointerleave` на `.hero` (`opacity` 200ms ease).

`.dots` в Bio.astro — исходный размер (`hero + 176px` десктоп, `hero + 700px`
планшет), **не** 100vw — пробовали растягивать на весь вьюпорт, чтобы курсор
ловился по всей ширине экрана, но это ломало `overflow-x: clip` на
`.page-container` (обрезало узор раньше физического края экрана на широких
мониторах) и раздувало масштаб узора в состоянии покоя. Спотлайт поэтому
работает только в пределах `.hero`, не всего вьюпорта — на практике этого
достаточно, курсор трогает узор именно там, где он есть.

Только мышь: `matchMedia('(hover: hover) and (pointer: fine)')` — на тач у
курсора нет физического аналога, эффект не подключается вовсе (мобильный
[HeroMobile.astro](src/components/mobile/HeroMobile.astro) не трогали).
Выключается и при `prefers-reduced-motion: reduce`.

### 7. Мелкие hover-переходы
`global.css`: `a, button, [data-interactive] { transition: background-color
150ms ease, opacity 150ms ease, color 150ms ease, border-color 150ms ease }` —
базовая заготовка, конкретных `:hover`-стилей под неё пока почти нет (объявлено
на будущее).

## Общая стилистика анимаций

**Плавная, но не медленная.** Reveal — быстрый отклик (`TAU 0.22`, было
уменьшено с 0.32 по прямой просьбе "чуть быстрее"). Никакого bounce/elastic/
overshoot нигде — везде монотонное приближение к цели (`ease`, экспоненциальное
затухание). Hover-переходы — быстрые, 150ms.

## Ограничения окружения (важно для итерации)

**В браузерной панели этого окружения (Claude Code) анимации не наблюдаемы:**
скриншоты приходят пустыми, а `requestAnimationFrame`/`IntersectionObserver`/
CSS-transitions заморожены в скрытой превью-панели. Можно проверить только:
- статическую геометрию (`getBoundingClientRect`)
- вычисленные (не анимированные) `getComputedStyle`
- математику формул руками

**"Ощущение" анимации (плавность кривой, скорость, тайминг) можно проверить
только на реальном устройстве пользователя** — итерация идёт по циклу
"пользователь тестирует на телефоне → присылает вербальную правку (`START`,
`TAU`, `END` в `reveal.ts` — единственные параметры, которые обычно крутят) →
правка вслепую → пуш → пользователь снова проверяет живьём". Не пытаться
подтвердить "на глаз" через браузерную панель — это технически невозможно здесь.

## Ограничения производительности / GitHub Pages

Нет серверного рендеринга анимаций и no build-time animation baking — все
эффекты чисто клиентские JS/CSS, отдаются как статические файлы. GitHub Pages —
обычный CDN для статики, ограничений на JS/CSS-анимации не накладывает (в
отличие от, например, лимитов serverless-функций). `animation-timeline: view()`
(нативный CSS scroll-linked API) осознанно **не используется** — нет поддержки в
Safari/iOS, а сайт смотрят с телефона, поэтому reveal реализован вручную через
rAF вместо нативного CSS API.
